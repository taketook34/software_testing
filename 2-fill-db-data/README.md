## 3.1. Опис скрипта наповнення

База даних заповнюється тестовими даними за допомогою Python-скрипта [`db_func.py`](db_func.py). Скрипт підключається до MySQL на Aiven і наповнює таблиці `users`, `deals`, `deal_item`, створені на попередньому етапі запитом з [`../1-db-creation-script/table_creation_query.sql`](../1-db-creation-script/table_creation_query.sql).

Скрипт виконує такі кроки:

1. **Заповнення таблиці `users`.** Генеруються користувачі з унікальними іменами, ролями (`client` — 85 %, `manager` — 10 %, `admin` — 5 %), прив'язаною біржею (Binance, Kraken, Coinbase, WhiteBIT тощо — лише для частини клієнтів) і датою створення в межах заданого періоду.
2. **Заповнення таблиць `deals` і `deal_item`.** Для кожної угоди генеруються користувач, дата, тип (`exchange`, `deposit`, `withdrawal`, `split_payout`), статус, коментар, версія та ознака нетипової угоди з причиною. До кожної угоди одразу формуються позиції `deal_item` (1–5 шт.) залежно від типу угоди: напрям `IN`/`OUT`, валюта (UAH, USD, EUR, USDT, BTC, ETH), сума в межах діапазону валюти, отримувач і статус, узгоджений зі статусом угоди.

Дані вставляються пакетами (за замовчуванням по 1000 рядків) з комітом після кожного пакета.

**Використані бібліотеки:**

| Бібліотека | Призначення |
|---|---|
| `pymysql` | підключення до MySQL (з SSL) і виконання запитів |
| `python-dotenv` | читання параметрів підключення з файлу `local.env` |
| `faker` | генерація реалістичних імен, дат і текстів (локаль `uk_UA`) |
| `argparse`, `random`, `datetime`, `decimal` (стандартна бібліотека) | параметри командного рядка, випадковий вибір із вагами, робота з датами та сумами |

## 3.2. Налаштування

Створення віртуального середовища та встановлення залежностей:

```bash
cd 2-fill-db-data
python3 -m venv fill-env
source fill-env/bin/activate
pip install -r requirements.txt
```

Параметри підключення:

1. Скопіювати `.env.example` у `local.env` і заповнити параметри з Aiven (Console → сервіс → Overview → Connection information): або `DB_SERVICE_URI`, або окремі поля `DB_HOST`, `DB_PORT`, `DB_USER`, `DB_PASSWORD`, `DB_NAME`. Якщо заповнено і те, і те, окремі поля мають пріоритет.
2. Завантажити з Aiven **CA certificate** і зберегти як `ca.pem` у цій папці (шлях можна змінити змінною `DB_CA_CERT`).

Файли `local.env` і `ca.pem` у git не потрапляють (див. `.gitignore`).

## 3.3. Запуск

Перед запуском активувати віртуальне середовище:

```bash
source fill-env/bin/activate
```

Перевірити підключення до БД і показати кількість рядків у таблицях:

```bash
python db_func.py --check
```

Заповнити таблиці (10 користувачів, 50 угод):

```bash
python db_func.py --users 10 --deals 50
```

Очистити всі таблиці (з підтвердженням):

```bash
python db_func.py --clear
```

Очистити таблиці та заповнити заново (1000 користувачів, 50000 угод):

```bash
python db_func.py --truncate --users 1000 --deals 50000
```

Показати всі доступні опції:

```bash
python db_func.py --help
```

**Опції скрипта:**

| Опція | За замовч. | Опис |
|---|---|---|
| `--users N` | 100 | кількість користувачів |
| `--deals N` | 1000 | кількість угод (на кожну 1–5 позицій у `deal_item`) |
| `--days N` | 365 | дати угод за останні N днів |
| `--batch-size N` | 1000 | рядків в одному пакеті вставки |
| `--locale` | `uk_UA` | мова згенерованих імен (`en_US`, ...) |
| `--seed N` | — | однакові дані при кожному запуску |
| `--truncate` | — | очистити таблиці перед заповненням |
| `--clear` | — | лише очистити таблиці |
| `--check` | — | лише перевірити підключення і показати кількість рядків |
